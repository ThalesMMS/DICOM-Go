# Third-party provenance

[`THIRD_PARTY_PROVENANCE.json`](../THIRD_PARTY_PROVENANCE.json) is the single
record of every file derived from another project: embedded tables, adapted
optional-module sources and imported test data. Human-readable notices live in
[`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md).

## Manifest format

`upstreams` maps an identifier (`<project>-<short commit>`) to the project,
repository, full 40-hex commit, SPDX license, and either a license file in this
module with its SHA-256 or a license URL. `notice_heading` names the heading in
`THIRD_PARTY_NOTICES.md` that must exist.

Each `artifacts` entry records:

- `path`: module-relative file.
- `upstream`: key into `upstreams`.
- `sha256`: SHA-256 of the committed artifact. `sha256_policy: "modified"`
  replaces the hash with a required `attribution` string for adapted source
  files that receive local changes.
- `distribution`: `test-data` (must live under a `testdata/` directory, never
  compiled or embedded), `embedded` (compiled into base-module binaries) or
  `optional-module` (ships only with an adapter module under `examples/`).
- `transformation`: how the artifact was derived.
- `sources`: upstream files with line range, SHA-256 of the file at the pinned
  commit and URL. A missing source hash needs an explicit
  `unverified_reason`.
- `generated_by`: the script that owns the entry, when generated.

## Verification

`go test ./internal/provenance` runs in `make test` and therefore in
`make check`. It fails when a listed artifact or license file is missing or
changed, when a notice heading is removed, when a file under
`testdata/upstream/` has no entry, when a test-data artifact lives outside
`testdata/`, or when required fields are malformed. `make provenance-check`
runs the same test alone.

Set `DICOMGO_REFERENCE_ROOT` to a directory holding reference checkouts named
`dcmtk/`, `GDCM/`, `VTK/` or `ITK/` to recompute every source hash from the
pinned commit with `git show` (the working tree is ignored, so `core.autocrlf`
does not matter). A missing checkout for a referenced upstream is an error, not
a skip.

## Importing upstream data

[`scripts/import-upstream-data.py`](../scripts/import-upstream-data.py)
regenerates `testdata/upstream/` from local checkouts at the pinned commits and
rewrites only the manifest entries it owns:

```sh
python3 scripts/import-upstream-data.py --reference-root ../..
```

It currently imports:

| Directory | Upstream | Content |
| --- | --- | --- |
| `testdata/upstream/gdcm/` | GDCM `2cd05d13` | pixel MD5 table, repaired-file MD5 table, media storage UIDs, reader stop offsets, `BLACK_LIST_READER`, overlay MD5 table |
| `testdata/upstream/dcmtk/lut/` | DCMTK `8d68392d` | `camera`, `monitor`, `printer` and `scanner` characteristic curves |
| `testdata/upstream/dcmtk/wlistdb/`, `wlistqry/` | DCMTK `8d68392d` | fictitious worklist database and query dumps |
| `testdata/upstream/dcmtk/*.json` | DCMTK `8d68392d` | sRGB/CIELab reference colors, oficonv GB18030 and GB2312 byte tables, tparser wrong-explicit-VR data sets, tftoa formatting vectors |
| `testdata/upstream/dcmtk/*_vectors.json` | DCMTK `8d68392d` | value vectors of tchval, tvrds, tvrdatim, tvrpn, tvrui, tmatch, tfrmsiz, tgenuid, tatof, tofdatim and tsrcodvl ([cross-checks](CONFORMANCE.md#dcmtk-value-vectors)) |
| `testdata/upstream/vtk/` | VTK `ac53123e` | license only, reserved for generated numerical fixtures |

Byte vectors embedded in DCMTK C++ tests (`tparser`, `tpread`, `tnesting`,
`tparseassoc` and similar) only make sense together with the test's
expectations. They are extracted by the feature that consumes them, as a new
importer function or a hand-written entry with the same fields.

`tparseassoc` and `tassocleak` build their A-ASSOCIATE-RQs in code rather than
storing bytes. `internal/dicomtest/association_vectors.go` regenerates the same
scenarios from the PS3.8 PDU layout and cites the tests (DCMTK `8d68392d`,
OFFIS BSD-3-Clause, no RSNA/CERIUM notice); no upstream bytes or code are
copied, so no manifest entry is needed.

The worklist dumps are read directly by `internal/dicomtest.ReadDCMTKDump`
instead of being converted to binary fixtures. The expected responses in
`net/dimse/testdata/dcmtk_mwl_responses.json` are output of DCMTK 3.7.0
`wlmscpfs` for those dumps, regenerated by `TestDCMTKWorklistOracle`; they
contain only the fictitious values of the imported database.

`testdata/upstream/dcmqi/tid1500.dcm` is not imported by the script: it is
the output of dcmqi 1.5.7's `tid1500writer` (`506306a0`, BSD-3-Clause) run on
synthetic metadata and images that `sr/testdata/dcmqi_tid1500_inputs.py`
builds. The metadata, `sr/testdata/dcmqi_tid1500.json`, follows dcmqi's
example and schema. Both files have manifest entries, and the directory's
README gives the regeneration command.

`dictionary/curated/catalog_gdcm.json` is embedded data owned by
`cmd/privatecataloggen -import-gdcm` (`generated_by`), which reads GDCM's
`privatedicts.xml` at `2cd05d13` from a local checkout and refuses any other
file hash; its notice is `dictionary/curated/LICENSE.GDCM`
([curated catalog](CURATED_PRIVATE_CATALOG.md#gdcm-private-dictionary-1146)).
`internal/standard/dicom.dic` is DCMTK's standard dictionary at `8d68392d`,
copied unmodified ([update procedure](../internal/standard/README.md)).
`internal/standard/sr_templates.tsv`, the PS3.16 template catalog behind
`sr.StandardTemplates`, is extracted from the standard itself (`part16.xml`,
PS3.16 2026d) by `cmd/srtemplategen` and carries no third-party material
([update procedure](../internal/standard/README.md)).


## Rules

`testdata/quirks` contains repository-owned synthetic GDCM quirk analogues and
an own public-API test harness, under the repository license. No upstream DICOM
files or codec implementations were imported. Its manifest and
[corpus guide](GDCM_QUIRK_CORPUS.md) record strict/recover expectations, source
hashes, GDCM 3.2.5 Windows observations and missing original vendor/large files.

- Implement behavior independently; do not copy production code from DCMTK,
  GDCM or VTK. Adapting code requires a recorded decision, an entry with
  `sha256_policy: "modified"` and an attribution header.
- Never import `dcmjpeg/libijg*`, `ofstd/oftest.h`, `dcmnet` sources carrying
  the RSNA/Washington University/CERIUM notices, `VTK/ThirdParty`, codecs
  bundled by GDCM or gdcmData DICOM files. The gdcmData corpus has no license
  file; tests read it from `DICOMGO_GDCMDATA_ROOT`.
- Imported data must not contain real patient data.
