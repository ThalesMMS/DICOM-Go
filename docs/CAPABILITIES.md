# Current capability and limitation scope

This document is the current entry point for deciding whether `dicom-go`
matches an integration. A package name or recognized UID does not imply full
support for every service, transfer syntax, SOP Class, clinical workflow, or
deployment profile. Detailed documents linked below define narrower contracts.

The opt-in [JPEG 2000 Part 2 collection encoder](JPEG2000_PART2_ENCODER.md)
supports 2–16 grayscale frames and an explicit matching decoder profile.
Complete independent Annex J decoding remains unqualified.

The [acquired 2D interpolation cost assessment](RASTER_2D_PLAN_COST.md) records
why retaining unchanged-geometry plans was not promoted: a fixed-profile ideal
cache reduced allocations without establishing consistent latency or P95 gains.


The [authored GDCM quirk corpus](GDCM_QUIRK_CORPUS.md) adds 29 small non-PHI
structural analogues with independent metadata/pixel oracles and separate
parse/preservation/decode/render outcomes. Expected refusals and missing original
vendor/large files remain explicit; a passing regression is not image support.

The optional [XDS-I.b transaction clients](XDSI_PROFILE.md) publish a stable
single-study KOS manifest over RAD-68 and retrieve its whole-image references
over RAD-69 SOAP/MTOM. They require explicit patient-domain mapping, source
identities, authorization and publication lifetime ownership. The controlled
TLS peer tests cover the declared transaction subset. Independent actor and
deployment qualification remain separate from those local tests. The
[earlier scope decision](XDSI_SCOPE_DECISION.md) records the original deferral.

## Supported surfaces

Volume brick planning includes bounded interpolation/central-gradient read
stencils (`render.VolumeBrickSampleStencil`) and monotonic per-frame pass/upload
accounting (`VolumeBrickBatchBudget`, `VolumeBrickBatchUsage`). These helpers
do not sample a rendered image. GPU shaders, atlas transport, frame publication
and native device lifetime belong to the consuming application.

[Discrete medial thickness](MEDIAL_THICKNESS.md) composes a Lee curve skeleton
and physical foreground-boundary-centre distance on regular anisotropic grids.
Sparse samples and original-component distributions have explicit undefined,
edge/cavity and resource policies; independent primitive comparisons and known
geometry quantify the discretization bias. No clinical thickness claim is made.

Recorded Basic Voice/General Audio uses the [bounded audio waveform profile](AUDIO_WAVEFORM.md):
class-specific PCM/G.711 decoding, aligned channel selection and typed rejection
of layouts outside the profile. Device playback belongs to the application.

## Required caller policy

[Local GLCM maps](LOCAL_TEXTURE_MAPS.md) expose four selected voxel-wise features
with fixed-width global/window quantization, physical rectangular radii,
masked/finite pair endpoints, deterministic directional reductions and bounded
regional execution. Independent direct and installed ITK 5.4.6 primitive
comparisons qualify authored fixtures; this is a research numeric profile.


- Simple file readers preserve compatibility by treating zero numeric budgets
  as unlimited. Untrusted inputs require explicit non-zero read, parse, pixel,
  nesting, element, and fragment limits appropriate to the deployment.
- Codec support is limited to the exact bit depth, component, photometric, and
  encode/decode profiles in the [codec capability matrix](./CODEC_CAPABILITY_MATRIX.md).
  Optional adapters may require separately installed runtimes.
- DIMSE uses plain TCP unless callers configure TLS. User Identity transports
  identity claims but does not authenticate or authorize them.
- DICOMweb Basic authentication requires certificate-verified HTTPS. The
  embeddable server requires an `Authorizer` unless the caller explicitly opts
  into unauthenticated operation.
- Network packages provide protocol mechanics and the documented opt-in audit
  spool. Applications supply protected credential storage, endpoint trust,
  retention policy, archive persistence and user-facing job state; spool retry
  and recovery do not establish remote delivery or repository retention.
- De-identification is metadata-policy enforcement, not automatic detection or
  removal of burned-in pixel PHI or recognizable visual features. Applications
  must review residual pixel and workflow risk.
- Repository tests and fixtures are synthetic or redistribution-safe. Live-peer
  interoperability is opt-in and must not use repository-default PHI data.

## Verification policy

`make check` is the baseline for the module. `make race` and `make leak` are the
offline concurrency gates. Native codec, long fuzz, and live interoperability
profiles remain explicit opt-ins documented by their dedicated runbooks.

Keep this file in present tense. Add a capability only with a public package or
command plus repository-local tests; describe prospective outcomes separately
without treating them as shipped behavior.

## WSI optical-path ICC

Optical Path Sequence profiles are resolved by frame/shared path identification
and TILED_FULL ordering, including non-numeric identifiers and concatenation
offsets. Root Image Pixel Description Macro ICC is never substituted. Identical
profile contents reuse a bounded ICC transform LRU. Missing, invalid or
unsupported RGB profiles retain stored colours with typed diagnostics; missing
or unknown path references and admission refusal prevent tile publication.
Profiles are limited to 1 MiB each, 8 MiB per instance and 32 MiB per resolver,
64 paths per instance, 4096 source instances and 4096 focal planes. The default
LRU admits 32 entries and 128 MiB conservative logical weight, not process heap.
Only existing RGB ICC transformations are supported; palette construction and
monitor profiling are outside this scope.
