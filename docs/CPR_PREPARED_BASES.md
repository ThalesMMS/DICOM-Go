# CPR request-owned prepared bases

This implementation passed scoped functional and race checks, the eight affected Twin caller tests and the integrated library `make check`. The measured before/after costs and tradeoffs below qualify the synthetic workload rather than guaranteeing speed for other inputs. Root's baseline profiling on macOS arm64 identifies repeated mapping (especially the nine-sample slab) and longitudinal column basis work; pthread coordination still dominates. Measured time reductions are limited to the synthetic longitudinal/slab cases below, with increased allocation and process peak RSS. The original four CPU profiles include complete requests/worker setup and profiled-process fixture setup, not isolated interpolation timing.

Longitudinal requests prepare rotated cross/slab axes once per column using the same stretched projection, degeneracy fallback, rotation and normalization sequence. Patient positions, resampling, arc length, output quality, interpolation selection, photometric mapping, physical/legacy slab samples and reducer order are unchanged. Transverse already prepared its basis once/request.

Slab sampling borrows the actual sampler volume under its existing immutable-generation lease. Only original regular, untilted, uncorrected geometry uses a ray-local recorded-position interval hint. An interior hit repeats exactly the original interval formula; a miss, endpoint, extrapolation or duplicate interval uses the existing positionToIndex search. No uniform-spacing approximation, floating-point coordinate reassociation, worker scheduling change or persistent cache is introduced. Tilt/irregular or regularized source input retains reference patient mapping.

Two Vec3 values per column use 48 bytes, bounded by checked multiplication to 393216 bytes (384 KiB) under the existing 8192 output-dimension limit. Preparation checks cancellation before allocation, every 64 columns and before publishing the complete array. Data belongs to one request and expires at return. The sampler closes after workers join. Input public volume geometry must not be mutated concurrently, as for PatientToVoxel. Volume.Close retains existing semantics: an already acquired lease may finish; a caller cancels/advances generation to prevent stale publication. Mac close and Windows cancelWork already do so. There is no new public close API or native GUI proof.

Prepared/reference comparisons require bit-identical scalar values/validity, Gray bytes, layout, spacing and plane metadata. Independent determinant inverse, Rodrigues rotation and tensor-product nearest/linear/cubic weights use absolute 1e-10 voxel and 1e-8 modality tolerances for differently ordered analytic calculations. Curved tubular fixtures cover all four modes, three interpolation modes, both payload formats plus unsigned packed16, rotation, every supported CPR slab reducer plus typed rejection of unsupported SlabSum, legacy/physical thickness, borders/ties, MONOCHROME1/2 and quantization-sensitive windows. Further tests cover tilt/irregular reference admission, bounded scratch/overflow, cancellation, generation supersession, path ownership, concurrent requests, source close while leased and release after worker completion. Root executed all 16 selected functional top-level tests and both selected lifetime/concurrency race tests successfully, without skips; this is not a full race suite or module baseline.

The frozen pre-optimization benchmark is 24 whole-frame cases with five repeats per strategy, warmed volumes and unchanged fixtures. Initial decode/I/O is excluded from timed frame operations; request preparation, worker coordination, sampling, window mapping and output are included. Root executed the original and candidate compiled binaries separately, with identical fixture code. No extra memory-worker campaign, preparation benchmark or CPU-profile rerun was executed. The integrated library `make check` passed in 293.23 seconds, and all eight affected Twin CPR caller tests passed in 91.26 seconds across two packages, without failures or skips. All 8711 repository source paths were identical before/after each execution. The Twin adapter was unchanged; its existing quantitative export test is a headless library oracle, not native application export qualification. No CI, external VTK runtime, GPU or native frontend qualification is claimed.

The first actual focal execution is preserved as FAILED (receipt 7a702913ec85a4c5a7b1424eeab76c05890efc59d9b79c8b8d8700b16950884a). Its Sum cases requested a mode the original CPR API rejects, and two residency checks compared cold pre-materialization state with the first canonical sampler payload. Generation2 retains those Sum cases as typed rejection/no-output checks against a literal original validator and warms the existing payload once before recording the residency baseline. Geometry, output/scalar/Gray oracles, tolerances, sample counts and production candidate are unchanged. Generation2 functional16 and selected race2 subsequently passed. The original failed receipt remains FAILED; production candidate code and all supported-mode geometry/weights/tolerances are unchanged.

All 18 longitudinal/slab median frame times were lower (candidate/baseline 0.544434–0.986525), while five of six transverse cells were slower by 1.46–3.80%; packed16 transverse linear was 0.31% lower. Longitudinal allocation bytes increased 19.96–20.84%, typically 10896 B and one allocation per frame; float32/slab9/linear added two median allocations. Transverse median allocations were unchanged, with 32–48 extra median bytes. Lower longitudinal time therefore trades for greater request allocation; there is no allocation reduction or universal time improvement.
