# dcmconv parity controls

These are explicit library-backed conversion controls, not complete GDCM/DCMTK
CLI emulation or de-identification. The default build remains pure Go with its
existing module graph. CI and application/viewer workflows are outside this
command's scope.

| Flag | Meaning and admission |
| --- | --- |
| `-remove-gl` | Alias for `-group-length remove`; an explicit different group-length policy conflicts. File Meta Group Length continues to be rebuilt. |
| `-remove-private-tags` | Recursively remove odd-group attributes, including private creators. Even-group File Meta Private Information is not selected. |
| `-remove-retired-tags` | Remove public tags marked Retired by the pinned standard dictionary, recursively. Unknown public tags remain. |
| `-split bytes` | Alias for the encapsulated Fragment payload cap, in bytes, including padding. Input range 2..4294967295; odd values round down to even. An explicit fragment-bytes must equal the effective cap; its original strict-even validation remains. Native targets refuse split; EOT and single-fragment restrictions remain the shared planner's policy. |
| `-generate-icon` | Generate one native 64×64 Icon Image Sequence using the public representative-frame generator, before main pixel rewrite/encoding. Existing icon is replaced only after successful generation. It does not change the stored main pixels. |
| `-icon-minmax MIN,MAX` | Finite modality-domain MIN < MAX, with generate-icon and monochrome source. Conflicts with auto mode. Two numeric tokens total ≤128 bytes. |
| `-icon-auto-minmax` | With generate-icon, ignore stored VOI and use usable monochrome modality min/max. |
| `-check-meta` | Report missing/mismatched Media Storage SOP Class, SOP Instance and Transfer Syntax identity fields, then rebuild through RebuildFileMeta. Reports codes/tags only. This does not infer the true encoding of a falsely declared syntax or run a general IOD validator. |
| `-root-uid root` | Apply this organizational root only to new SOP Instance UIDs generated by this conversion call. Empty preserves UUID-root defaults. The root must be a valid UID, have room for the library's minimum random suffix, and exclude reserved DICOM/2.25 roots. Conflicts with uid-policy preserve. Root alone does not force generation on equivalent copies. Study/Series IDs and predecessor references are preserved; legacy upgrade retains its existing UID policy. |

Private/retired filtering uses `object.StripAttributes` with default metadata
bounds of 64 sequence levels, 100000 elements and 100000 items. It precharges
whole containers before allocation, including siblings and removed branches.
Failures return zero counts and leave the object unchanged. These are metadata
container counts, not RSS or raw-buffer limits. The API requires exclusive object
ownership and an open, immutable borrowed source. Raw buffers remain borrowed;
real nested deferred bulk retains original item identities through a private
provider clone. Copied/unbound item addresses and unverifiable nested non-bulk
nil representations are refused. Every retained root nil deferred value is admitted only
with a unique registered reader reference matching tag, VR, length and root path,
and a validated physical source range (including a validation-reader hook for
non-bulk text). RootValueLocation ignores nested occurrences but refuses repeated
root records; its query scans existing metadata without allocation or I/O.
Undefined-length root Pixel Data requires encapsulated source syntax; its recorded
length covers the actual BOT/fragment/delimiter bytes, not the UndefinedLength
sentinel. The retained VL form must match the original recorded header; neither
defined-to-undefined nor undefined-to-defined relabeling is admitted. A source-backed
nil root remains authenticated with VLzero; nil values with unset lengths are
refused, while explicit source-free empty values remain unchanged. The filter is
not general writer or IOD validation; a nil zero-length placeholder still follows
the writer's existing representation rules. Materialized empty values serialize normally. Active filter
options validate retained source metadata even if no attribute is selected. Strip checks cancellation before and after the reference probe.
Reference admission uses a cursor-preserving SeekCurrent availability probe and
zero payload reads; it is not an absolute zero-I/O guarantee. Materialized text
is preserved. The API does not re-identify private blocks or rewrite references.

Metadata preparation holds the original source open through icon generation and
bounded private precursor serialization. It rechecks the source digest and file
identity before accepting that precursor and strictly reparses it. The normalized
byte cap defaults to 1 GiB or the positive configured read-total-byte cap. Source
and destination aliases, including existing hardlinks/symlinks, are refused.
Publication remains the existing TranscodePath/dataset-only implementation; this
is not a second publication engine. The digest proves admitted precursor input
stability during preparation, not arbitrary later namespace mutations or an RSS
cap. Private temporary files are removed on failure/success. Read recovery uses
the same metadata controls and cancellation checks after its existing upgrade.

The icon generator's existing default caps are 1024 frames, 16 Mi pixels,
64 MiB native/input, and 100000 fragments; it decodes only the selected frame.
Window overrides require monochrome. YBR_ICT/YBR_RCT, 1/32-bit and other sources
unsupported by Generate remain explicit errors even when a main decoder exists.
`-compress-icons` is the existing separate lossless transcoding control. No empty
or zero icon is emitted on codec/budget/cancellation/error refusal.

## Repair data after complete Pixel Data

```sh
dcmconv -repair-trailing-data -o intact.dcm input.dcm
```

This copy-only mode takes just an input and a new output path. It uses
`pixeldata.RepairPart10TrailingData` to retain the original Part 10 bytes
through the end of the single root integer Pixel Data element. Native pixels
must match the image dimensions and even Value Field length. Encapsulated
pixels must have complete Items and the Sequence Delimitation Item.
The staged copy passes an ordinary structural Part 10 read with strict
reserved-byte checking and matching File Meta identity before publication.
The result reports the retained and discarded byte counts.

The suffix must start with an invalid root header. A plausible element
header, including Data Set Trailing Padding, is a refusal. Healthy files,
missing or truncated pixels, open fragments, Deflated datasets, and existing
destinations are also refused. Encapsulated validation covers framing.
Codestream decoding and IOD validation have separate entry points. Ordinary
conversion continues to read inputs using its own policy.

The path API caps input and disk staging at 2 GiB by default, and
`TrailingDataRepairOptions.MaxInputBytes` can lower the limit. Retained
metadata reads are capped at 64 MiB with a 4 MiB per-value cap outside
Pixel Data. The scan also bounds tokens, elements, fragments and nesting.
The caller owns input stability and the destination directory during the
operation. The source is opened read-only and the destination is published
create-only. A post-publication error carries a report with `Published=true`.

See [DICOM PS3.5 §7](https://dicom.nema.org/medical/dicom/current/output/chtml/part05/chapter_7.html),
[DICOM PS3.5 Annex A.4](https://dicom.nema.org/medical/dicom/current/output/chtml/part05/sect_A.4.html)
and [DICOM PS3.10 §7](https://dicom.nema.org/medical/dicom/current/output/chtml/part10/chapter_7.html)
for dataset framing and File Meta.

## Explicit optional OpenJPEG source-checkout profile

Build from this library checkout, which must include the nested adapter module:

```sh
go build -modfile=dcmconv_openjpeg.mod -tags jpeg2000_openjpeg -o dcmconv-openjpeg ./cmd/dcmconv
./dcmconv-openjpeg -ts 1.2.840.10008.1.2.4.90 -j2k-backend openjpeg -j2k-tile 64,64 -j2k-resolutions 4 -o lossless.dcm input.dcm
./dcmconv-openjpeg -ts 1.2.840.10008.1.2.4.91 -j2k-backend openjpeg -allow-lossy -j2k-rate 20,5 -j2k-tile 64,64 -j2k-resolutions 4 -o lossy.dcm input.dcm
```

The alternate modfile/sum compose the existing adapter with a local replace and
leave default go.mod/go.sum untouched. This is not a module-ZIP profile (nested
modules are excluded from the root module ZIP) or an implicit codec registration.
Each conversion owns its decoder/encoder registries; no default registry or
environment variable is modified. Explicit rate, tile or resolution controls
force re-encoding even for an equivalent source syntax, so they are never silently
ignored; backend/executable selection alone retains normal copy behavior. Invalid
recovery/rewrite names are rejected before probing the runtime. Qualified `opj_compress` 2.5.4 is required,
selected by `-j2k-executable`, existing DICOM_GO_OPENJPEG_COMPRESS, or PATH. The
existing adapter retains its finite process timeout/frame/output/concurrency
limits and cancellation/join/temporary-file lifecycle. Unknown or unavailable
profiles, wrong runtimes and unsupported input return errors; no fallback encoder
or StepSize approximation is used.

| Target | Coding |
| --- | --- |
| Part 1 `.90` lossless-only | Reversible 5/3, rate 1, no component transform. Optional tiles and resolutions use OpenJPEGEncoderOptions and existing encodeWith. Explicit j2k-rate is refused. Zero API fields preserve original defaults. |
| Part 1 `.91` | Requires allow-lossy and explicit compression ratios: ≤16 finite rates 1..10000, strictly decreasing, ≤64 bytes per numeric token and ≤1024 bytes total. Ratios are target coding layers; codestream/Part 10 overhead prevents an exact file-byte ratio promise. Uses the existing irreversible encoder, preserving RGB photometry. |
| Other syntax/profile | Part 2, HTJ2K, motion JPEG 2000 and JPEG XL encoders are not part of this profile. Coding helpers require an explicit .90/.91 target and backend. |

Tile dimensions are paired positive 1..65535; resolutions are 1..33 (0 selects a
finite geometry-derived default, at most six). For `.90`, the smallest actual
edge tile must hold 2^(levels-1) samples on both axes. This deliberately
conservative policy can refuse geometry OpenJPEG itself may encode; it never
clamps an explicit request. The `.91` coding validation remains the existing
adapter contract. OpenJPEGEncoderOptions lossless coding fields are refused by
`.91` constructors; use OpenJPEGLossyOptions there. No lifecycle is duplicated.

The encoder accepts unsigned 8/16-bit mono/RGB, BitsStored 8..BitsAllocated,
matching HighBit, and interleaved RGB. Signed/palette/1/32-bit/YBR inputs are
refused unless an existing explicit rewrite makes them eligible. Optional decode
is used for compressed sources and readback in this profile, including generated
icons; generated YBR_ICT/RCT icons still retain their generator limitation.

## Qualification

Focused tests distinguish pure option/admission proofs from real codec/runtime
proof. Optional interop tests require the additional explicit `dcmconv_interop`
tag and qualified DICOM_GO_OPENJPEG_COMPRESS/DECOMPRESS paths; they fail when
required runtimes are absent, rather than silently passing/skipping. `.90`
controls are checked in actual SIZ/COD markers and all decoded 8/12/16-bit mono/RGB
samples through both the adapter core and independent opj_decompress. `.91`
checks actual tile/resolution/layer/wavelet markers, lossy method/root metadata,
and independent decoder agreement/PSNR. These are synthetic correctness proofs,
not PACS, viewer, clinical or performance acceptance. Legacy optional-runtime
skips are recorded separately in gate provenance. GDCM's pre-existing limitations
with some split JPEG/JPEG-LS layouts must not be generalized into interoperability
claims for all caps/codecs.
