# Hough 2D phantom candidate profile

`imagefilter.HoughLines2D` and `HoughCircles2D` are opt-in proposals from an immutable binary edge `Volume`, one slice. Existing `CannyResult.Edges` can be supplied; this API does not duplicate edge detection. It does not identify anatomy, create persisted ROIs or perform 3D work. The frozen synthetic phantom profile passed actual private qualification on Darwin arm64, including both independent fitted-contour and direct ideal analytic-geometry checks. Clinical measurement accuracy remains unqualified; integration baselines remain a separate gate.

Coordinates are source pixel-center physical plane coordinates `(x*SpacingMM[0],y*SpacingMM[1])`, millimeters. Source origin and patient directions remain with the caller. Region is explicit half-open source indices, never implicitly the full image. Input samples must be exactly0/1, including outside Region; spacing is positive finite on both axes. Input is never mutated; errors/cancellation return no partial result. Returned candidates own their geometry and support counts; votes are not probabilities.

Lines use `rho=x*cos(theta)+y*sin(theta)`, signedrho(mm), normaltheta(radians)in[0,pi). Rho bins have aligned inclusive endpoints; theta bins are aligned half-open. Suppression compares rho and normalangle modulo pi with rho sign reversal across the0/pi seam. Circle centers/radii use aligned inclusive millimeter grids; centers are within Region's pixel-center bounds and radius is positive. `AngleBins` samples the full perimeter orientation. Every source edge can vote at most once into each center/radius cell, even when several angles quantize to that cell. Ties are deterministic: theta/rho for lines, radius/y/x for circles. Suppression widths and the maximum candidate count are explicit. A physical circle can be an index ellipse with anisotropic spacing.

`MinVotes` declares required visible support. Binary edges have no retained intensity polarity: inverted contrast is equivalent only when caller preprocessing produces the same edges. Texture, intersecting edges, thick contours, edge-preprocessing settings and incomplete visibility can create ambiguity/false positives. There is no automatic confidence or visibility inference.90degree partial arcs have no qualified sensitivity guarantee; full and210degree arcs are eligible only in the frozen phantom recipe, not arbitrary clinical targets.

## Bounds and cancellation

Zero limits select finite ceilings:1Mi source samples,64MiB logical owned working bytes,100million work units; overrides may only lower them. MaxCandidates1..64, circleAngleBins8..4096; line angular count at most4096. Admission reserves uint32 accumulator cells, circle-plane uint32dedup stamps, two float64trig values per angle,64bytes per candidate and4096bookkeeping bytes. Caller input and Go runtime overhead are excluded, so this is not an RSS guarantee. Integer overflow/nonfinite extent/alignment failure rejects before allocation. Work admission conservatively reserves all ROI pixels as edges and all candidate scans/suppression passes; one work unit means a validation/scan sample, edge-angle voting pair or accumulator cell visit, not a hardware instruction. Actual work may be lower for sparse/empty data. `HoughReport` reports admitted bytes, worst-case operations, actual operations and ROIedge count.

Cancellation is checked before allocation, through validation/voting/peak search/suppression at bounded1024work-unit intervals, and before return. No workers/goroutines/background state or results survive an error. Request-local memory is released through normal Go lifetime; no global accumulator/cache is added. Higher-dimensional inputs fail explicitly.

## Frozen qualification and actual independent reference

Before implementation, the recipe declared 64/96/128-pixel phantoms at (.5,.5), (.4,.8), (1,1) mm spacing; scale-paired circle radii 6/10/14 mm, line normals 0/45/90 degrees, intersecting lines, full/210-degree arcs, deterministic sparse noise of at most 0.5% of source pixels, inverted contrast through existing Canny, and empty images. Thresholds remained unchanged after outputs. Single-line minimum support is half the labeled contour; circle minimum support is a third, at least eight votes; intersecting lines use 40 votes. The candidate cap is four. These are explicit phantom presets, not automatically inferred settings for other targets.

Actual focal qualification passed all six top-level tests. All 27 single-line phantoms had one matching candidate and zero geometrically unmatched candidates. The intersection test established both target lines present and at most one unmatched candidate; its log does not record an exact unmatched count. All 18 eligible circle phantoms had one matching candidate: 9/9 full contours and 9/9 210-degree arcs. Seventeen cases had zero unmatched candidates; the 64-pixel, (.5,.5) mm, 210-degree case had one. Thus every eligible truth was present and every eligible phantom met the preregistered maximum of one geometrically unmatched candidate. This does not measure one-to-one assignment sensitivity or clinical sensitivity.

The historical generation-2 eligible cases passed physical error assertions against independently fitted labeled-contour references (PCA for lines and algebraic least squares for circles): line rho error at most maxspacing + .5 mm and normal error at most 2 degrees modulo pi; circle center error at most 1.5 * maxspacing + .5 mm and radius error at most maxspacing + .5 mm. Depending on spacing, these bounds are 1–1.5 mm for rho/radius and 1.25–2 mm for circle center. Region/seam tests separately cover the narrower configured grids. The focal log records PASS and independent fitted contours, but does not record each detector geometry/error or a measured maximum error. Fitted-contour residuals must not be relabeled as detector errors.

Labeled raster contours are fitted by independent orthogonal PCA and algebraic least-squares geometry in the Go tests. A separate own Python PCA/circumcircle oracle passed 27 analytic cases; this validates independent mathematics only, not detector performance. Anisotropic (.4,.8) mm tests passed using physical circles that are ellipses in index coordinates. Deterministic noise was added after fitting the labeled reference; the reported target-presence/unmatched results include that noise. Inverted-contrast Canny produced identical edge masks and candidates in its tested case. Empty input produced no line or circle candidates.

The unqualified 90-degree challenge (96 pixels, .5 mm spacing, 10 mm radius, minimum eight votes) returned four proposals: center/radius (24,24)/10 mm with 29 votes; (25.5,23.5)/9 with 10; (23.5,25.5)/9 with 10; (23.5,22.5)/11 with 9. The true geometry is present, alongside three alternatives. This case illustrates visibility ambiguity and does not extend the full/210-degree qualification or its false-positive acceptance gate to 90-degree arcs.

Observed report ranges for qualified phantoms were: lines 376,592 logical bytes, 1,018,576–3,242,704 actual work units, 1,572,616–3,796,744 reserved work units; circles 9,176 logical bytes, 64,176–337,704 actual work units, 3,715,206–14,848,134 reserved work units. These counts are algorithm visit counters, not instructions or RSS.

## Qualification metric interpretation

The executed single-truth tests use candidateHits>=1 to establish detected truth presence. Several candidates within that same truth tolerance are geometrically matching candidate hits, not distinct true targets or additional sensitivity. Intersecting lines use two independent presence flags, one per true line. Sensitivity is detected eligible truth objects / eligible truth objects, never candidate-hit count / truth count. The executed false-positive count is candidates outside every declared truth tolerance; it is a geometric unmatched-candidate metric, not one-to-one assignment precision. Duplicate matching candidates are reported as duplicate proposals and bounded by NMS/candidate cap; no one-to-one precision statistic has been computed or claimed. Original thresholds/tolerances/workloads remain unchanged; the actual results above report target presence, matching candidate count and unmatched count separately.

## Actual direct analytic-truth qualification

The original geometry criterion also requires direct comparison with the ideal line rho/normal and circle center/radius that generated each phantom. Generation 5 retained every fitted-reference candidate-hit/false-positive assertion and added a separate `analyticHits >= 1` assertion to each existing single-truth case. A single candidate must jointly satisfy rho and angular limits, or center and radius limits, against that ideal geometry using exactly the same original tolerances. No fixture, implementation, threshold, preset or budget changed.

Root actually reran the two existing top-level phantom tests with the amended assertions: both passed without skips or failures. Each of the 27 single-line and 18 eligible circle cases logged exactly one candidate jointly matching analytic truth. Across these logged matching candidates, maximum line rho error was 0.24516600406096245 mm and maximum normal error was 0 radians; maximum circle center error was 0.5 mm and maximum radius error was 0 mm. These are observed maxima only for these matching candidates in the declared cases, not errors for every returned alternative or unqualified geometry. The intersection's existing direct ideal-line checks also passed; its per-target errors were not individually logged. Original fitted-reference presence/FP checks remained passing, including the one geometrically unmatched proposal in the eligible 210-degree circle case.

The amended two-test phase took 5.799010083079338 seconds including the Go test invocation; it used Go 1.27.1 Darwin arm64, the same bounded 90-second test/180-second outer limit and 8 MiB log ceiling. The receipt reports exact source guards before/after, exit zero, no surviving owned process group, child reaped and output drained.
