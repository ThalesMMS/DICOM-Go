# Regional neighbourhood filtering

`PlanRegions` and `FilterRegions` extend the existing z-slab primitive to a requested X/Y/Z output region. Reader/writer regions carry global origin and size; samples are x-fastest. Supported filters are the existing median, bilateral and blockwise NLM options. Recursive Gaussian, unsharp, global-statistics diffusion and N4 are deliberately not admitted as finite-halo filters. No Twin or file adapter is implemented.

The driver only computes requested output samples. Median clamps at true volume boundaries, bilateral omits outside taps, and NLM preserves the original global block-centre grid, last-axis centre, patch/search traversal and block-average order. The NLM read halo is twice the patch radius plus the search radius in each axis. Compact input strides do not change global clamping or candidate coordinates. Existing slab views retain their original layout when the regional size field is zero.

Median's histogram-versus-selection admission is data-dependent. A bounded pass reads the complete logical source once to classify the same global domain as the whole-volume operation, including signed zero. No generic source needs an extra metadata interface. This can make small-ROI median I/O worse than expected; it must be disclosed in measurements. Classification does not compute output outside the requested region. Its reads count against the optional request read-byte bound.

The plan accounts compact input plus halo, output, parameter arrays, all worker buffers and NLM block estimates before creating them. It validates overflow and rejects a bound below its conservative minimum with `RegionalBudgetError`. Zero working bound uses the slab default. A tile hint is reduced to fit; tiles execute serially with kernel workers using the existing shared parallel scheduler. Parameter and scratch backing arrays are reused within the request. No source data is retained between calls. `MaxReadBytes` can reject excessive planned reads before allocation; reported planned bytes are a conservative bound, while actual read bytes count successful reads.

The bound covers request-owned backing arrays with fixed metadata allowance. Reader/writer storage, application volumes, allocator overhead, goroutine stacks and Go/runtime state are external. It is not an RSS limit. NLM may compute entire block estimates for blocks contributing to requested samples; it does not run the filter for unrelated output voxels. Overlap between adjacent input windows is reread in this first implementation; its amplification is bounded by the plan and optional read-byte bound, and must be reported rather than claimed as an overlap-cache saving.

Before each read and after read/filter, cancellation is checked. Only a fully computed tile is passed to the writer and counted complete after writer success. Prior successful tiles remain on cancellation or failure. Writer transactionality is external: a writer returning an error may already have changed its destination, but that tile is not counted complete. Buffers are request-local; workers join before return. Reader/writer implementations must honor context, complete their buffer contract and not retain reused slices or mutate source during a request.

Authored tests compare every requested float32 bit with whole-volume median/bilateral/NLM across small anisotropic grids, impulses, ROI boundaries, tile layouts and worker counts; untouched output retains a sentinel. Separate tests cover signed-zero global classification, overflow/budget rejection before I/O, cancellation/reader/writer errors and repeated requests with different sources. Additional variants include Y/Z and 3-D NLM patches, block steps 1 and 3 with terminal centres off the regular grid, different median/bilateral radii and a sparse single-voxel ROI. The five regional functional tests and seven existing affected tests passed in an authorized execution (12 top-level tests, 9.5164 seconds). Budget/overflow rejection before I/O, cancellation/error commit fences and concurrent different-source calls are included. This is functional evidence, not a race-detector qualification.

Independent requested-region, halo and replicated-border evidence was obtained with the existing ITK 5.4.5 SDK, source commit `f51594ad88194a72cdc06a314dafff709fcdc2e9`. An independently authored C++ public-API `MedianImageFilter` harness emitted its actual input region and 226 float32 values represented by their binary32 bits for eight fixed cases: whole, corner, interior and last regions on 7×5×4 and 7×5×1 images, using anisotropic sample radii [1,2,1] and [2,1,0]. The SDK was reused without rebuilding it. A separately executed Go comparison passed one top-level test and eight subcases without skips or failures (21.8677 seconds); observed padded/cropped input regions and requested output bits matched exactly. Independent review confirmed the raw outputs and provenance. The fixture case IDs `4d` and `1d` denote Z depths of three-dimensional images, not four-dimensional filtering.

This external reference covers median and the driver's requested-region/halo/border contract. It does not assert bilateral or NLM equivalence to ITK algorithms. Whole-volume equivalence for those existing kernels is covered by the local bit comparisons above. `TestRegionalITKRequestedRegionOracle` remains opt-in through `DICOM_GO_REGIONAL_ITK_FIXTURE`; an absent fixture produces an explicit skip and cannot substitute for the actual reference qualification. No reference algorithm was transcribed and expectations were populated only from the independently executed harness.

`BenchmarkRegionalSmallROI` used a 1024×64×2 source with spacing [0.7,1.3,2.1], output origin [500,25,0] and size [24,12,2] (576 samples). Slabs used a 4 MiB working bound; regions used a 1 MiB bound with tile hint [12,6,1]. Each of the six fixed cases performed a whole-Slabs bit comparison before timing and then one timed operation (`-test.benchtime=1x -test.count=1 -test.benchmem`, GOMAXPROCS=2). The test binary was compiled once from the canonical regional overlay. Observations were recorded on Darwin arm64 with Go 1.27.1, in one fresh `/usr/bin/time -l` process per case:

Each cell is a single observation; there are no repeat distributions, confidence intervals or statistical speedup claims. The regional operations had lower measured ns/op and allocated bytes in these fixed cases, while allocation counts increased for all three kernels. These observations do not establish a universal benefit or a representative end-to-end workload result.

Median read 527,872 bytes regionally versus 524,288 for slabs: 3,584 extra bytes (about 0.68%). Its bounded global classification pass reads the entire source before tile halos and preserves the existing data-dependent histogram/selection semantics. Bilateral and NLM read 5,120 and 3,456 bytes in these small-ROI cases; other radii, tile layouts and sources can amplify halo reads. The plan and optional read-byte cap bound that amplification; no overlap cache is claimed.

The benchmark timer excludes initial source/output setup and reference/preflight calls but includes the selected complete filter operation. Each process executes **all three unconditional whole-Slabs reference preflights in the parent benchmark**, even when its selector chooses only one child case, plus the selected child's preflight. Thus process peak RSS and real/user/system time include those references, fixture arrays, setup and runtime. They are actual whole-process observations, not isolated kernel peak memory, retained heap, a working-budget measurement or a demonstrated RSS saving. Process time has the resolution printed by Darwin `time`; the first median/slabs process's 0.33 seconds is preserved rather than normalized away.

The integrated library `make check` passed on macOS 27.0.1/Darwin arm64, Apple M4 Pro, in 405.5810 seconds, with exit 0, no timeout/signals and its owned process group drained and reaped. Source guards were exact across this execution. This baseline used the same five regional Go postimages as the functional, independent-reference and cost qualification. The present amendment only records that result; the final documentation check is recorded separately after documentation composition. Default baseline success does not imply that every opt-in prerequisite was enabled: the ITK comparison skips when its fixture is absent, while the separately qualified actual eight-case comparison above ran with the recorded fixture and no skips. The selected Twin caller result is recorded separately; no new adapter is introduced. No Twin/file adapter, native desktop, GPU, PACS or clinical qualification is implied. The independent native work for other filters is separate from this library capability.

The original G1 static review blocked a copy of NLM state containing an atomic scratch-pool counter. G2 uses plain planning parameters and a request-owned pointer to the existing NLM kernel after budget approval; no atomic runtime state is copied. G2 also rejects unrepresentable converted radii before doubled-window arithmetic. The G1 source and static report remain preserved; no runtime failure has been relabeled.
